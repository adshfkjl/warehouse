# 回滚手册

本文档用于 WMS 单库区试点失败、停止条件触发或现场负责人要求恢复时的受控回滚。回滚优先保证人员和设备安全，再保证任务、库存、托盘和库位账可追溯。不得通过删除数据、改写状态历史或修改旧 PLC 时序完成回滚。

## 1. 回滚授权和窗口

回滚只能由现场负责人授权，设备负责人负责物理安全，仓储负责人负责实物和账面封存，WMS 运维负责人负责服务/数据库，安全负责人确认隔离条件。填写：

| 项目 | 内容 |
| --- | --- |
| 窗口编号 | `BLOCKED：待填写` |
| 授权人和时间 | `BLOCKED：待现场负责人签字` |
| 触发原因 | `BLOCKED：待填写` |
| 试点范围 | `BLOCKED：库区/托盘集合` |
| 目标版本 | `BLOCKED：待批准版本` |
| 备份校验值 | `BLOCKED：待填写` |
| 证据目录 | `BLOCKED：待填写` |

## 2. 立即停止

1. 现场负责人宣布回滚，停止创建和下发新的 WMS 设备任务。
2. 设备负责人按现场规程停止或急停；WMS 不直接写寄存器，也不假设物理动作已经停止。
3. 对 `SentToPlc`/`Executing` 任务走取消/停止协议；停止结果未知时转 `PhysicalStateUnknown`，不得标记 `Canceled` 或释放锁。
4. 记录所有活动任务、设备任务号、幂等键、资源锁、Outbox/Inbox、报警、装载点和现场托盘位置。
5. 断网、断电或 PLC 重启时，按试运行手册记录最后确定状态，恢复后先只读对账。

## 3. 账面和实物封存

- 导出试点范围内库存余额、库存流水、单据、任务状态历史、资源锁、设备日志、异常工作项和消息记录。
- 仓储负责人逐托盘核对实际库位、装载点、数量、重量和批次；差异建立盘点/异常工作项。
- 未完成设备动作、超时和未知结果不得自动补发；物理状态由设备负责人和仓储负责人共同确认。
- 账实不一致时使用授权的库存调整/人工物理确认流程，保留原始状态，不删除原流水。

## 4. 软件和数据库恢复

1. WMS 运维负责人确认数据库备份可读、校验值匹配，并在隔离测试库先演练恢复。
2. 生产恢复必须使用批准的数据库备份和幂等迁移脚本；不得在没有备份和负责人批准时执行降级迁移。
3. 恢复服务到批准版本，保留配置摘要和二进制校验值；禁用自动设备提交，先启动只读监控。
4. 恢复 Worker 时保留任务状态、Outbox/Inbox 和资源锁；Worker 只能查询已有设备任务，不得重发无法对账的命令。
5. 健康检查、日志、任务状态和数据库迁移版本确认后，才允许人工对账。

## 5. 回滚后验证

| 检查项 | 通过条件 | 证据 |
| --- | --- | --- |
| API/数据库/Worker | 健康检查可用，版本与批准包一致 | 健康快照/日志 |
| 任务状态 | 未知任务仍为 `PhysicalStateUnknown` 或有人工结案记录 | 状态历史 |
| 消息 | Outbox/Inbox 按幂等键和版本去重，无重复处理 | 消息导出 |
| 库存 | 流水可重算，余额无负数，无重复流水 | 库存对账 |
| 托盘/库位 | 每个试点托盘唯一归属，实物和 WMS 一致 | 盘点表 |
| PLC | 旧 PLC 配置/时序未被修改，设备负责人确认安全 | 配置校验和/签字 |

## 6. 回滚结束和重新试点

回滚只有在上述检查全部通过、现场负责人批准、仓储/设备/WMS 运维/安全负责人签字后结束。重新试点必须重新执行只读监控和双跑，不能直接从回滚状态恢复自动下发。若任何未知事实、设备能力或账实差异未解决，状态保持 `BLOCKED`/`FIELD_PENDING`。

本手册当前只完成文档和模拟回归设计，未执行真实数据库恢复、PLC 停止、断电、急停或现场切换。
