# 现场试运行手册

本文档对应 Task 7.2。它定义现场负责人、仓储负责人、设备/PLC 负责人和 WMS 运维人员在受控窗口内的试运行顺序。本文档不授权修改旧 PLC 时序，也不允许 Agent 代替现场负责人签字。

## 1. 门禁和责任

| 门禁 | 需要的证据 | 当前状态 |
| --- | --- | --- |
| `AGENT_VERIFIED` | 模拟设备契约、自动化测试、恢复脚本和文档检查通过 | 已具备 |
| `HUMAN_CONFIRMED` | 负责人确认作业口径、报警分级、重量/时间阈值、责任人和停机窗口 | `HUMAN_PENDING` |
| `FIELD_VERIFIED` | 真实 PLC 受控回归、急停/断网/断电恢复、账实核对和回滚签字 | `BLOCKED` / `FIELD_PENDING` |

责任人必须明确为具体姓名和联系方式：

| 角色 | 责任 |
| --- | --- |
| 现场负责人 | 批准窗口、急停授权、停止/回滚决策和最终签字 |
| 仓储负责人 | 单据、托盘、库位、盘点和账实核对 |
| 设备/PLC 负责人 | PLC 状态、报警、急停、复位、物理动作和设备隔离 |
| WMS 运维负责人 | 服务、数据库备份/恢复、日志、任务状态和证据归档 |
| 安全/质量负责人 | 现场安全条件、人员隔离和异常放行 |

在表格中填写负责人、电话、窗口开始/结束时间和证据目录；未填写不得进入受控动作。

## 2. 试点前置条件

- 旧系统和新 WMS 的版本、配置、数据库备份和回滚包已登记；生产凭据不写入仓库。
- 已完成模拟 PLC、设备契约、任务调度、离线/超时/物理未知、消息重放和服务重启测试。
- 现场基线中 PLC 编号、IP、端口、寄存器偏移、完成码、报警字典、装载点阈值和设备并发能力均有负责人签字；未确认项继续保持 `BLOCKED`。
- 现场具备急停、断电、网络隔离、PLC 重启和人工搬运/封存措施，安全负责人在场。
- 新 WMS 默认只读监控；未取得试点批准前，不创建会下发 PLC 的生产任务。
- 试点仓库只选择一个库区、明确托盘集合和明确停止时间，不跨库区扩展。

## 3. 执行顺序

### 3.1 只读监控

1. 启动 WMS、健康检查和日志采集；确认 API、数据库、Worker、设备网关和 Outbox/Inbox 状态。
2. 只读取 PLC 状态、报警、装载点和任务结果，不写寄存器、不启动设备动作。
3. 连续记录一个完整观察周期，核对 PLC 状态、WMS 状态、库位/托盘主数据和旧系统画面。
4. 任何地址、完成码、报警位、重量或在线判据不一致时停止，登记 `BLOCKED`，不得猜测修复。

### 3.2 单库区双跑

1. 导入或建立试点范围内的 WMS 基础资料和托盘清单，生成导入摘要并由仓储负责人确认。
2. 旧系统继续作为现场控制方；WMS 只建立镜像单据、库存和任务，不向 PLC 下发。
3. 用相同的入库、出库、移库和盘点样例在 WMS 与旧系统分别计算，比较库位、托盘、数量、重量和状态。
4. 双跑差异必须逐项解释并形成签字记录；差异未关闭时不得进入受控动作。

### 3.3 受控设备试点

1. 现场负责人宣布窗口开始，设备负责人确认安全区域、急停可用、人员撤离和设备处于允许状态。
2. 先执行一条低风险、可人工核对的模拟网关任务；再按批准顺序执行单托盘入库/出库/移库。
3. 每条任务记录 WMS 任务号、幂等键、设备任务号、源/目标库位、托盘号、装载点、开始/结束时间和设备结果。
4. 设备结果只通过统一结果处理器进入 WMS。成功前不增加/扣减库存；失败、超时或 `PhysicalStateUnknown` 保留锁并转异常处置。
5. 每完成一条任务，仓储负责人现场核对托盘实际位置、装载点、库位和重量，再允许下一条。

### 3.4 人工对账和批准

- 按托盘逐项核对 WMS 库存、库位、托盘位置、任务状态、设备日志和现场实物。
- 盘点差异必须有复盘、原因、审批人和库存调整流水；不能直接改余额或把未知任务标为成功。
- 设备任务号无法查询、结果版本冲突或网络超时的任务必须保持 `PhysicalStateUnknown`，由现场负责人决定人工确认或回滚。
- 只有现场负责人、仓储负责人、设备负责人和运维负责人共同签字后，才能扩大范围或批准切换。

## 4. 异常和停止步骤

### 急停

1. 任何人员发现人身/设备风险，立即按现场急停规程操作并通知现场负责人和设备负责人。
2. WMS 停止新任务入队；已发送/执行任务不得直接标记成功或取消。
3. 记录急停时间、设备状态、任务号、报警码、托盘和库位；等待设备负责人确认安全。
4. 设备物理状态无法确认时进入 `PhysicalStateUnknown`，保留资源锁，禁止自动重试。
5. 只有设备负责人确认复位安全、现场负责人批准后，才可执行状态读取和人工对账。

### 断网或 PLC 离线

1. 停止新的设备提交；不重复发送最后一个超时命令。
2. 记录最后一次确定的设备任务号、结果版本和 WMS 任务状态。
3. 若旧接口不能按任务号查询，任务保持 `PhysicalStateUnknown`；若可查询，先查询并保存设备观察证据。
4. 网络恢复后先只读探测和状态对账，确认设备未继续动作，再决定失败、成功或人工处置。

### 断电或 PLC 重启

1. 按现场电气规程断电/上电，人员和设备安全由设备负责人负责。
2. WMS 服务可重启，但不能清空任务、资源锁、Outbox/Inbox 或状态历史。
3. PLC 恢复后先读取急停、报警、位置、托盘和任务状态；未知物理结果必须人工核对。
4. Worker 重启只查询已有设备任务，不自动重复发送未知命令。

### 人工接管

人工接管不是简单把状态改为 `Succeeded`。必须填写操作者、二次授权、物理位置、源/目标库位、设备状态、原因、照片/点检证据和库存校正流水；结果进入 `ManualIntervention`，并保留原任务历史。

## 5. 成功、停止和回滚条件

### 成功条件

- 试点范围内每条批准任务均有设备任务号、结果和完整状态历史。
- 入库/出库/移库成功后的 WMS 库存、托盘和库位与现场实物一致。
- 重复消息、服务重启、网络恢复和设备查询不会产生重复动作或重复库存流水。
- 无未解释报警、无未处置 `PhysicalStateUnknown`，或每个未知任务都有人工处置记录。
- 四类负责人完成签字，证据目录可复核。

### 停止条件

- 人身安全、设备安全、急停、报警或现场隔离条件不满足。
- PLC 地址/完成码/报警语义与基线不一致，或出现无法解释的物理动作。
- WMS 与现场托盘/库位/库存无法对账，或出现双占用、丢托盘、重复动作。
- 数据库、Outbox/Inbox、日志或备份不可用，无法恢复任务证据。

### 回滚条件

- 任一停止条件无法在窗口内消除。
- 现场负责人判断继续运行风险不可接受。
- 需要修改旧 PLC 时序、寄存器或生产接口才能继续。

回滚时停止 WMS 新任务、保留全部状态和日志、由设备负责人确认现场安全，由仓储负责人完成实物封存/对账，再按 [`docs/rollback-runbook.md`](rollback-runbook.md) 恢复批准版本。不得删除未知任务或直接释放未确认资源锁。

## 6. 证据留存

每次窗口至少保存：批准单、人员名单、版本和配置摘要、健康检查、任务/设备日志、PLC 状态和报警快照、托盘/库位对账表、数据库备份校验值、异常处置、回滚结果和四类负责人签字。证据目录使用 `yyyyMMdd-window-id`，生产密钥和完整连接串必须脱敏。

当前结论：本文档和模拟回归清单可标记 `AGENT_VERIFIED`；真实试点、签字和设备动作保持 `BLOCKED`/`FIELD_PENDING`。
