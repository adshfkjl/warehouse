# WMS 作业优先、统计分析与实时点位视图设计

## 1. 目标与范围

本设计服务于立体仓库 WMS 的管理 Web 和 PDA 入口，基于旧程序已有的入库、出库、移库、盘点、库位、托盘、装载点、PLC/设备和异常功能重新组织交互。

本阶段只固化交互、读模型和后续实现边界，不实现前端、统计任务或生产数据接入。WMS 仍是库存和业务任务的唯一业务所有者；设备网关只提供设备状态和观察结果。

## 2. 工作台方向

采用“作业优先 + 轻量实时监控”。一级导航保持高频作业：工作台、入库、出库、移库、盘点、库存/库位、设备任务、异常中心。工作台首屏以待办和快捷作业为主，实时监控作为辅助区域，不替代作业流程。

首屏布局：

- 左侧为角色化快捷入口：新建入库、创建出库、发起移库、开始盘点、库位/托盘查询。
- 中央上方为待入库、待出库、待移库、盘点差异等作业计数。
- 中央主体为当前作业队列，显示优先级、任务号、来源/目标、设备、状态、耗时和异常入口。
- 右侧为只读实时监控：PLC/网关在线状态、堆垛机或设备状态、装载点有货/空闲、告警数量和数据新鲜度。
- 底部为需要关注的工作项：物理状态未知、停止请求、库位/托盘锁定、超时和待人工确认。

不同角色只改变快捷入口和可见指标，不改变业务状态机。操作员优先看到待办和扫码入口；主管增加统计摘要、异常趋势和任务成功率；维护人员增加设备健康和报警详情，但仍不能从监控卡片直接写 PLC 寄存器。

## 3. 统计分析交互

### 3.1 统计指标

第一版定期统计以下指标：库存总量和重量、库位利用率、入库量、出库量、移库量、盘点差异、设备任务成功率、异常数量。所有指标必须带统计周期、仓库/库区筛选、数据生成时间和数据新鲜度。

### 3.2 汇总周期与数据边界

- 汇总周期可配置为小时、日、周、月；默认以日汇总，执行时间由配置指定，不在代码中写死。
- 汇总任务以 WMS 业务流水、任务状态历史、库存余额、库位容量和设备观察结果为来源，不读取 ERP 数据库，不把 PLC 原始寄存器直接作为库存统计来源。
- 每个统计批次有 `periodStart`、`periodEnd`、`generatedAt`、`sourceVersion` 和幂等键；重复执行同一周期必须安全重放。
- 当前周期的实时值与已完成周期的汇总值分开显示，避免把尚未结算的数据伪装成最终统计。
- 统计失败进入异常/运维工作项，不能覆盖上一次成功汇总；页面显示“数据延迟”及最近成功时间。

### 3.3 图表与页面

统计页面保持业务工具风格，首屏包含：

- KPI 数字卡：库存总量、库位利用率、今日入库、今日出库、任务成功率、未处理异常。
- 趋势折线图：按选定周期展示入库、出库、移库和异常数量。
- 库位利用率柱状图或分区对比图：按库区、巷道和货架筛选。
- 任务状态堆叠图：成功、执行中、失败、超时、物理未知和人工处置。
- 盘点差异列表：差异数量、重量、原因、审批状态和跳转入口。

图表必须支持时间范围、库区、物料/批次和任务类型筛选，并能跳转到对应单据、任务、托盘或异常详情。图表是只读投影，不直接触发库存调整或设备动作。

## 4. 实时点位物品视图

### 4.1 导航与空间层级

库存/库位页面提供“点位视图”，按仓库 → 库区 → 巷道 → 货架 → 层 → 库位逐级筛选。第一版采用可缩放的二维货架网格和层级选择器，优先保证库位编码、状态颜色和点击命中准确；不把 3D 动画作为第一版依赖。后续如现场需要，可在同一查询契约上增加三维渲染。

点位颜色只表达业务状态：空闲、占用、预留、锁定、设备执行中、异常/物理未知、禁用。颜色之外必须显示文字或图标，不能只依靠颜色传达状态。

### 4.2 点位详情

点击库位打开详情抽屉，显示：库位编码、巷道/货架/层、容量和可用容量、当前托盘号、物料编码与名称、批次/有效期、数量、重量、库存状态、入库时间、最近业务任务、锁定者/锁到期时间、关联装载点以及最近设备观察时间。

托盘或物料查询可以反向定位点位，并显示该托盘的业务轨迹和当前任务。无物品点位显示“空库位”；设备正在执行或结果未知时显示锁定原因和处置入口，不允许直接编辑成空闲。

### 4.3 实时刷新与一致性

- 第一版以短周期轮询 API 为默认刷新方式；若设备网关未来提供回调，回调和轮询统一写入同一观察/Inbox 处理服务。
- 每个点位快照带 `observedAt`、`sourceVersion` 和 `freshness`；超过阈值显示“数据可能过期”，不把旧值标记为实时。
- 点位视图是只读查询。入库、出库、移库、盘点、取消、停止和人工物理确认必须跳转到相应业务流程，并继续经过权限、锁和状态机。
- 设备或数据库不可用时保留最近快照并明确显示离线/过期，不虚构当前物理位置。

## 5. 接口与读模型边界

后续实现应提供版本化只读契约，建议包括：

- `GET /api/reports/summary`：指定周期和范围的 KPI 汇总。
- `GET /api/reports/trends`：趋势序列和状态分布。
- `GET /api/warehouse/points`：按空间层级、状态、物料、托盘筛选点位快照。
- `GET /api/warehouse/points/{locationCode}`：单点位详情和最近观察。
- `GET /api/warehouse/pallets/{palletCode}/position`：托盘当前位置和轨迹摘要。

统计汇总和点位快照属于可重建读模型，不得成为库存或任务的第二业务真相。查询接口只读 WMS 已确认的库存、库位、托盘和设备观察数据；物理未知状态必须原样透传。

## 6. 验收与门禁

设计验收关注：操作员能在首屏进入核心作业；主管能看到实时状态和统计摘要；点位点击能定位当前托盘/物料；过期、锁定、未知和离线状态有明确展示；图表可跳转到业务明细；页面不包含 PLC 时序或寄存器写入。

后续实现必须补充统计周期幂等、重复汇总、失败不覆盖、点位快照版本去重、过期提示、空间筛选、权限和只读边界测试。真实 PLC 点位、设备报警语义、现场数据新鲜度阈值和统计口径仍需 `HUMAN_PENDING`/`FIELD_PENDING` 确认。
